# toki-quiz-gen

Spec file → validate → render template → embed artwork → one self-contained Toki In-App quiz HTML.

Replaces the hand-made "read CSV → hand-write `QUIZ` → run scripts → upload to Drive" loop described in
`Pawly/PRD/Phase 1.6/marketing/Toki_Quizzes_HANDOVER_2026-10-09.md`. Web-side tooling only: no App, iOS or service changes.

## Install and run

Needs Python ≥ 3.11 and Node ≥ 18 (for `autocheck`); macOS `sips` compresses the artwork (Pillow is the fallback).

```bash
python3.12 -m venv .venv && .venv/bin/pip install -e '.[dev]'
.venv/bin/toki-quiz-gen --help
.venv/bin/toki-quiz-gen specs/elemental_mysticism.yml --artwork art/elemental_mysticism --out out/
```

Output: `out/Toki_Quiz_{PascalSlug}_InApp_EN_{YYYY-MM-DD}.html` (`--date` overrides today). The run

1. loads + structure-checks the spec (all schema errors are reported together),
2. runs the rules below and refuses to write anything if one fails,
3. compresses every `{dog,cat}-{band.artwork}.png` with `sips -Z 640 -s formatOptions 60` and inlines it as base64,
4. renders `templates/quiz_template.html` (`<title>`, `const QUIZ`, `const ART` are the only holes),
5. fails if the page is over 1.3 MB (`--max-bytes`),
6. runs `autocheck` on the result.

Other entry points: `verify_logic <spec.yml|page.html>…` and `autocheck <page.html>…` (both exit non-zero on failure).

## Spec

YAML with exactly the engine's `QUIZ` fields (handover §3): `id titleShort eraTitle h1 sub trending startLabel tipTemplate
calcLines scoreBase meterEnds dims dimKeys DOG_QUESTIONS CAT_QUESTIONS BANDS disclaimer`, plus optional `scoreDisplay`,
`artAlt {dog,cat}` (result-image alt text), `slug` (file-name PascalCase; default from `id`) and `questionsCsv`.

* Every option: `t` (behaviour only), `s` (integer score), `prof: {k, v}` (profile signal).
* Every band: `min max theme(A–D) artwork(kebab slug) name tagline chip descDog descCat traits tipDog tipCat`.
* CSV adapter: `questionsCsv: file.csv` supplies `DOG_QUESTIONS`/`CAT_QUESTIONS` from columns
  `species,tag,q,t,s,prof_k,prof_v` (one row per option).

## Rules

| Rule | What it enforces |
|---|---|
| band coverage | per species, closed-interval bands have no gap, no overlap, and cover `[scoreBase+ΣminOpt, scoreBase+ΣmaxOpt]`; dog and cat ranges match |
| structure | same question count per species; every option has `s` + `prof`; every band has `descDog` + `descCat` |
| no score leak | option text has no `+older`, `–younger`, `(3)`, `(+2)`, `3 pts` … |
| species imagery | dog side mentions one of leash/park/recall/walk/fetch/bark; cat side one of litter/perch/slow blink/window/high ground/FIC (whole words) |
| autocheck | `<script>` compiles; dog and cat each run min/max/mixed answers on a stub DOM; `.result-art` with embedded image, `ic-` icons, no emoji, only the species' own questions served, expected band at both extremes, dog About ≠ cat About |

## Layout

* `src/toki_quiz_gen/templates/quiz_template.html` — engine/CSS shell lifted 1:1 from the shipped quizzes (icons, `ART`,
  `showResult`, `saveSessionLog`, `postMessage` untouched; only the result-image alt text now reads `QUIZ.artAlt`).
* `specs/` — the 6 shipped quizzes converted back to specs, plus the pilot `elemental_mysticism.yml`.
  `karma_check` and `love_language` have one dog-side stem reworded to mention the park (no score change) so they satisfy
  the species-imagery rule; the shipped Drive HTML is untouched.
* `art/elemental_mysticism/` — **placeholder** art generated by `scripts/make_placeholder_art.py`. Design's real
  `{species}-{band}.png` files go in the same folder.
